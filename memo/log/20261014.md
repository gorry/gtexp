## 取り込みの履歴に「何を取り込んだか」を出す
- ユーザーの指示：取り込みの履歴に、何を取り込んだかを出す
- 履歴（imports）はタイムラインだけを記録していたので、Google Takeout・Foursquare Swarm・名前・メモ・タグとブックマークの取り込みも記録するようにした。`kind` と `detail`（内容の JSON）の列を足し（前の DB には起動時に足す。前の行はタイムライン）、タイムライン以外は件数の列を 0 にする。Takeout と Swarm の zip をまとめて送ったときは、別々の行にする
- 表は「日時」「取り込んだもの」（種類とファイル名）「内容」にした。内容はタイムラインは期間と滞在・移動の件数、Takeout は置き換えた種類ごとの件数、Swarm はチェックインと店の数、名前・メモ・タグとブックマークは読み込んだ数
- データを削除したときは、その種類の履歴の行も消す（タイムラインは前から履歴ごと消していた）。概要の「最後の取り込み」はタイムラインの行から取る
- 確かめたこと：型チェック・ビルド。使い捨ての試験用データで、前の形の imports に列が足されて前の行がタイムラインになること、4 種類の取り込みがそれぞれ記録されること、Swarm・タイムラインを削除するとその行だけ消えること、ブラウザーで表の表示

## 取り込みの履歴を 20 件ずつ出す
- ユーザーの疑問：取り込みの履歴は何件まで保存・表示されるか。答え：上限はなく、すべて保存し、すべて表示していた（タイムラインの元のファイルも、取り込むたびに gzip で残していて上限がない）
- ユーザーの選択で、画面の履歴を新しい 20 件ずつ出し、「もっと見る（残り n 件）」で続きを出すようにした（保存はこれまでどおり全部）。元のファイルの扱いは変えていない
- 確かめたこと：型チェック・ビルド
