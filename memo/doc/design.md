# 設計方針

G Timeline Explorer（略名 gtexp）の方針と、そう決めた理由。機能の詳細は [spec.md](spec.md)、元データの形式は [timeline-format.md](timeline-format.md)。

## 目的
「過去に行った場所のデータベースアプリ」。いつ・どこに行ったかを、日付・場所・検索・集計などいろいろな形で調べる。

- 場所は Google マップ / Google Earth で開ける
- 検索・集計して、各種ファイルに書き出せる
- データは自分で記録するのではなく、Google タイムラインのエクスポートをときどき注ぎ足す
- パソコン（大きい画面）と Android の両方で使う

## 構成

```
[Android] Google マップ ─手動エクスポート─▶ JSON ─「共有」→ PWA ─HTTPS POST─┐
[パソコン] ブラウザで JSON を選んで送る ─────────────────────────────────┤
                                                                         ▼
[自前サーバー Linux / FreeBSD]  Apache / nginx (HTTPS) ─▶ Node.js（127.0.0.1:8787）
                                          ├ 取り込み・検索・集計の API
                                          ├ SQLite（利用者ごとの data/users/<名前>/gtexp.sqlite と、全員で使う data/shared.sqlite）
                                          └ 画面（PWA）の配信
```

## 決めたことと理由

### 手動エクスポートは避けられない
タイムラインは端末内に暗号化して保存され、外から読む API がない。Takeout からも取れない。
そのため、どの作り方でも「エクスポートしたファイルを読み込む」作業は残る。工夫できるのは受け渡しの手間だけなので、PWA の Web Share Target で「共有 → アプリ」の数タップで送れるようにした。

### ネイティブアプリではなく PWA
- Windows で Android アプリを動かす仕組み（WSA）は終了しており、同じアプリをそのまま大きい画面で使うことはできない
- Google マップの公式 SDK は Windows のネイティブアプリには使えない。両方で同じ地図を出すなら Maps JavaScript API が素直
- 自分で位置を記録しない（バックグラウンド動作が不要）、OS との深い連携もない（ファイルの読み書きと外部 URL を開くだけ）ので、PWA で足りる

### データは自前サーバーに置く
端末ごとに取り込む必要がなく、パソコンと Android で同じデータと、同じ名前・メモを見られる。

### 店名は Places API で取らず、自分で名前を付ける
- エクスポートには placeId しかなく、店名を出すには Places API（Place Details）が必要
- 店名は有料の区分で、使った分だけ課金される
- Google の規約で、取得した店名・住所などは保存できない（placeId は無期限、緯度経度は 30 日まで）
- そこで、場所ごとに**自分で付けた名前・メモ・タグ**を保存する（自分のデータなので自由に保存・検索できる）。どの店かは、Google マップで開いて確かめる

### 住所と地点名は、保存してよいデータから取る
- Google の店名・住所（Places API・Geocoding API）は保存できないので、保存してよいデータから取り、取得方法ごとに別々に持つ（place_labels）
- 国土交通省「位置参照情報」（街区・大字町丁目）：住所。zip を手元に置き、回数の制限なし
- OpenStreetMap の施設名：日本の OSM データ（Geofabrik）から名前の付いた施設を取り出して手元に置く。公開の Overpass サーバーは混雑で応答しないことが多く、Overpass 自身も公開サーバーに頼るアプリを推奨していないので使わない
- OpenStreetMap の住所：Nominatim（公開サーバー）。利用規約を守るため、cron で毎時少しずつ（15〜25 秒に1回）取って貯める。海外の地点にも住所が付く
- Google Takeout（保存した場所・ラベルを付けた場所・保存リスト）：自分のデータの書き出しなので保存してよい。保存した場所は Google の店名そのもので、滞在先と座標が一致するものを同じ場所とみなす。取得方法の中で最優先
- 位置参照情報と OSM は近くの施設・代表点からの推定なので、別の店や隣の町になることがある。自分で付けた名前が常に最優先

### サーバーは Node.js + SQLite
- 100MB を超える JSON を一度に読む処理があり、画面と同じ TypeScript で書けて型を共有できる
- `node:sqlite`（Node 標準）を使えば、ネイティブモジュールのビルドが要らず、Linux でも FreeBSD でもつまずかない
- esbuild で1ファイル（`dist/server.mjs`）にまとめる。動作時に外部ライブラリは要らない

### 取り込みは「新しいファイルの期間で置き換え」
エクスポートには毎回全期間が入っている。セグメントの境界は Google 側の再処理で変わることがあるので、1件ずつ照合する方式は重複の恐れがある。
そこで、新しいファイルの最初の時刻以降をすべて削除して入れ直し、それより前は残す。自分で付けた名前・メモは別テーブル（place_notes）なので消えない。
元ファイルは gzip で `data/users/<利用者名>/imports/` に残し、DB を作り直せるようにしている。

### データを入れる人を分ける
- 利用者のデータ（自分のタイムラインのエクスポート、自分の Google Takeout の書き出し）は、利用者が画面の「ファイルを選ぶ」で送る。サーバーに入れなくても済むようにする
- 全員で使う参照データ（位置参照情報、OpenStreetMap の施設、Nominatim からの定期取得）は管理者がサーバーで入れる。画面には状態と出典だけを出し、入れかたは管理者向けの文書（`deploy/README.md`）に書く

### 利用者は独立、DB は利用者ごとに分ける
- 利用者どうしは独立していて、共有はしない。管理画面は作らず、コマンドで管理する
- 利用者ごとに DB を分ける（`data/users/<名前>/gtexp.sqlite`）。全テーブルに利用者の列を足す方式は、すべての問い合わせに条件が要り、書き漏れるとほかの人の記録が見えてしまうので採らない
- 参照データ（位置参照情報・OSM の施設。OSM は数百万件）は利用者ごとに持つと無駄なので、`data/shared.sqlite` にまとめて ATTACH する。利用者の DB に同じ名前のテーブルを作らなければ、SQL はテーブル名だけで済む
- Nominatim の問い合わせの間隔の決まりはサーバー全体で守る必要があるので、fetch-osm は全員の分を 1 つの流れで順に取る

### 認証
- 利用者名とパスワード（scrypt のハッシュを data/shared.sqlite に持つ）
- ログイン状態は「利用者名＋有効期限＋HMAC 署名」の Cookie（既定 180 日）。サーバーにセッションを持たない。署名に利用者ごとの値を混ぜ、パスワードを変えたらログイン中の端末を無効にする
- Apache の Basic 認証は、インストールした PWA や Android の共有経由の送信と相性が悪いので使わない
- 失敗が 10 分に 10 回を超えたら受け付けない

### サーバーで展開してビルドし、そのフォルダーで動かす
- 配布は GitHub のリポジトリ。サーバーに `git clone` して `npm ci && npm run build` し、展開したフォルダーをそのまま実行場所にする（設定・DB・ログも同じフォルダーに置き、Git の管理対象外にする）。更新は `git pull` とビルドのやり直しだけで済む（`deploy/update.sh`）
- 手元でビルドして送る形は、手順が増え、送り漏れや古いファイルの残りが起きやすいので採らない
- 主な対象は Linux（systemd、Apache / nginx）。FreeBSD（rc.d、Apache / nginx）でも動かせるよう、OS ごとの設定例を `deploy/linux/`・`deploy/freebsd/` に分け、共通のスクリプトは OS を問わず動く sh で書く
- 外に置くのはサービスの定義と Web サーバーの設定だけ。手順は [deploy/README.md](../../deploy/README.md)

## アプリ名
**G Timeline Explorer**（略名 gtexp）。画面に出る名前は正式名、URL・ファイル名・サービス名などは略名。
Google のブランドガイドラインでは他者のアプリ名に「Google」を入れることを認めていないので、アプリ名や外部サービスに送る User-Agent には「Google」を入れない。データの出どころとしての「Google タイムライン」「Google マップ」という言い方は、事実の説明なので使ってよい。

アプリ名・略名・バージョン・著作権表示・URL などの定数は、リポジトリ直下の `Profile.ini` にまとめてある。このファイルは著作者だけが書き換える（プログラムや AI は読むだけ）。使い方は [spec.md](spec.md) の「アプリ名・バージョン（Profile.ini）」。
