# GUI メッセージ・文言の課題と改善指針

本ドキュメントは、gtexp（G Timeline Explorer）の画面（`src/client/`）およびサーバーが画面へ返すメッセージ（`src/server/`）における、「一般ユーザー向けの GUI 文言として不自然な箇所」の分析結果と、修正の指針・対象一覧をまとめたものです。
開発者および開発を担当する AI の双方が参照し、今後の実装・修正の基準とすることを目的としています。

---

## 1. 現状の GUI 文言に見られる主な問題点（総評）

これまでの開発（特に `2026-10-13` の「UI の文言を見直す」以降）において、「専門用語や実装名を出さない」「一般の利用者が読む前提にする」というルールを適用しようとした結果、**逆方向の過剰適応（オーバーコレクション）**と**仕様説明と UI テキストの混同**が起きています。

具体的には、以下の 4 つの問題がアプリ全体に広がっています。

### (1) 内部アルゴリズム・閾値・サーバー事情の過剰な露出（「AI から開発者への実装報告」調）
ユーザーが画面を操作する上で知る必要のない内部パラメータ（`2m 以内`、`30m 以内`、`50m 以内`、`300m 以内`、`前後 10 分（150m 以内）`、`15〜25 秒に1回`、`全国分で 1 分ほど`）や、データ管理の裏事情（`zip そのものはサーバーに残しません`、`zip に入っていなかった種類は前のまま`、`時間が二重にならないように`）が、そのまま画面の説明文として長々と表示されています。

- **原因**：AI が「自分が実装したロジックの正確さ・工夫・制約」を開発者に説明するトーンのまま、GUI のヘルプや注記を書いてしまっている。
- **原則**：GUI には**「ユーザーにとってどう動くか・何をすればよいか」**だけを簡潔に書き、具体的な距離閾値・秒数・サーバー上のファイル削除挙動などの内部仕様は `memo/doc/spec.md` にのみ記載する。

### (2) 標準的な UI 用語を避けたことによる不自然な言い回し（訓読み・口語への過剰な言い換え）
「技術用語を避ける」というルールを過剰に解釈し、Web アプリで一般的に定着している標準的なカタカナ語・漢語まで避けて、日常会話のような訓読み動詞（「足す」「入れる」「外す」「変える」「送る」「暦」など）や独自の造語（「入れ子」「予備のコード」）に置き換えてしまっています。

- **原因**：「専門用語を出さない＝すべて大和言葉・平易な話し言葉で言い換える」という誤った変換が行われている。また、プログラム上の概念である `hierarchyLevel > 0`（Nested）を直訳した「入れ子」をそのまま UI 用語として採用してしまっている。
- **原則**：世の中の一般的な Web サービスやスマートフォンアプリで標準的に使われている言葉（**追加、削除、編集、変更、登録、取り込み、カレンダー、バックアップコード、ユーザー名**など）を素直に使う。

### (3) 役割・画面構成と噛み合わない案内（「サーバーの管理者が〜」の反復とリンクずれ）
- 一般ユーザーの画面（保存リストや「このアプリについて」）のあちこちに「サーバーの管理者が〜入れます」「サーバーの管理者が〜用意すると〜」という他人事のような説明が繰り返し表示されている。
- 「今すぐ調べる」ボタンを「データの取り込み」画面から「このアプリについて」画面へ移動したにもかかわらず、場所詳細画面（`src/server/labels.ts`）の未調査メッセージが `取り込み画面の「今すぐ調べる」で調べます` のまま残っている。
- バックグラウンド処理（`src/server/osm.ts`）の停止理由（`pid 12345...` や `Nominatim から 429 が返ったので止めました`）など、本来サーバーログに出すべき開発者・管理者向け文字列がそのまま GUI に赤字表示される作りになっている。

### (4) AI 特有の冗長な文体と細切れの読点
- `確認のため、パスワードと、認証アプリの確認コードを入力してください。`
- `ほかの端末では、ログアウトされます。`
- `時間をおいてから、もう一度試してください。`
- `チェックが入っている場所に #xxx が付いた状態になります。チェックを変えて「決定」を押してください。`

のように、文節ごとの不要な読点（「では、」「と、」「から、」）や、動作を噛み砕いて言い聞かせるような冗長な説明文が目立ちます。UI のメッセージは一目で意味が取れるよう、短く引き締まった文体にする必要があります。

## 2. 用語・表記の統一ルール（今後の基準）

| 避ける表現（現状） | 標準的な UI 表現（修正後） | 備考 |
|---|---|---|
| 利用者 / 利用者名 | **ユーザー** / **ユーザー名** | 画面見出しの「ユーザー情報」と統一する |
| 暦 / 暦を隠す | **カレンダー** / **カレンダーを隠す** | |
| 入れ子 / 入れ子の場所 | **施設内**（または **施設内の滞在**） | Google タイムラインの親施設内の滞在を表す語として自然な表現にする |
| 予備のコード / 作り直す | **バックアップコード** / **再発行する** | 2段階認証の一般的な用語に合わせる |
| 足す（ブックマークに足す 等） | **追加する** / **追加** | |
| 外す（ブックマークから外す 等） | **削除する** / **削除**（タグは **外す** または **解除**） | |
| 名前を変える / 名前を付ける | **編集**（または **名前・メモを編集**） | `NoteForm` は名前・メモ・タグを同時に扱うため |
| ファイルを送る | **ファイルを取り込む**（または **ファイルの選択**） | |
| まだ入れていません / 〜に入れたデータ | **未取り込み（まだ取り込まれていません）** / **〜に取り込み** | |
| 今のパスワード / もう一度 | **現在のパスワード** / **新しいパスワード（確認）** | |
| もう一度（再試行ボタン） | **再試行**（または **再読み込み**） | |
| 画面 / 作成（「このアプリについて」） | **クライアント** / **ビルド** | バージョン情報の項目名 |
| タイムラインにある / ない（フィルタ） | **訪問あり** / **訪問なし** | 「ない」単体では意味が通りにくいため |
