# 仕様

機能・画面・API・データベース。方針は [design.md](design.md)、元データの形式は [timeline-format.md](timeline-format.md)。

## 場所の名前と住所
- 元データには placeId しかなく、店名などは入っていない（[design.md](design.md)）
- 画面に出す名前は、次の順で最初に見つかったもの
  1. 自分で付けた名前（place_notes）
  2. 自宅・職場などの種類
  3. **いちばん良い地点名**（Google Takeout のラベル・保存した場所、Foursquare Swarm のチェックイン、OpenStreetMap の施設名。取得方法の優先順）
  4. **いちばん良い住所**（下の取得方法の優先順）の短い表記（例：千代田区丸の内一丁目）
  5. 「名前なし」
- 名前と別に住所があれば、一覧などで名前の下に添える

### 住所・地点名は取得方法ごとに保存する
- 取得方法によって細かさや表記が違い、完全な住所にならないこともあるので、場所ごと・**取得方法ごと**に別々に保存する（place_labels。主キーは placeId＋取得方法）
- 項目：種類（住所 / 地点名）、全体の表記、短い表記、取得方法ごとの細かい項目（JSON）、基準点までの距離、更新日時
- 一覧や名前の代わりには、取得方法の優先順位（`src/server/labels.ts`）でいちばん良い住所を1つ使う
- 場所の詳細では、取得方法ごとの状態を優先順に並べる：住所あり（基準点までの距離つき）/ 調べたが見つからなかった（取得方法ごとの理由つき。例：街区は都市計画区域に相当する範囲だけ）/ まだ調べていない。データを入れていない取得方法は出さない
- 名前・メモ・タグの検索は、どの取得方法の表記にも当たる

| 取得方法（source） | 種類 | 内容 | 優先順位 |
|---|---|---|---|
| `takeout-label` | 地点名 | Google Takeout の「ラベルを付けた場所」。30m 以内（設定 `takeoutLabelM`） | 10 |
| `takeout-saved` | 地点名 | Google Takeout の「保存した場所」の店名。同じ場所とみなす 2m 以内（設定 `takeoutSameM`）。同じ場所の滞在先がない店は、30m 以内（設定 `takeoutNearM`）でいちばん近い滞在先 1 か所にだけ付ける（ほかの店が付いている滞在先は使わない。2 店が同じ滞在先を選んだら近いほう）。保存リスト・コメント・保存日・Google マップのリンクも持つ | 20 |
| `swarm-checkin` | 地点名 | Foursquare Swarm のチェックインした店。チェックインの時刻を含む滞在先（端末の位置から 300m 以内）。場所ごとに、いちばん多くチェックインした店 | 22 |
| `takeout-review` | 地点名 | Google Takeout の「クチコミ」を書いた店。店ごとに、30m 以内（設定 `takeoutNearM`）でいちばん近い滞在先 1 か所にだけ付ける。評価・本文・書いた日も持つ | 25 |
| `takeout-addr` | 住所 | 同じ保存した場所の住所（番地まで） | 30 |
| `takeout-mymap` | 地点名 | Google Takeout の「マイマップ」の地点。地点ごとに、30m 以内（設定 `takeoutLabelM`）でいちばん近い滞在先 1 か所にだけ付ける。名前が座標だけの地点は使わない。地図・フォルダーの名前とメモも持つ | 35 |
| `isj-gaiku` | 住所 | 国土交通省「位置参照情報」（街区レベル）。いちばん近い街区の代表点（150m 以内）。例：千代田区丸の内一丁目9番。住居表示の地域は「〇番」、それ以外は地番なので「〇番地」 | 40 |
| `isj-oaza` | 住所 | 国土交通省「位置参照情報」（大字・町丁目レベル）。いちばん近い代表点の町丁目（10km 以内）。境界の近くでは隣の町丁目になることがある | 50 |
| `osm-poi` | 地点名 | OpenStreetMap（手元に置いた日本のデータ）。60m 以内の名前の付いた店・施設・駅など | 60 |
| `osm-addr` | 住所 | OpenStreetMap（Nominatim）。海外の地点にも付く | 60 |

### ラベルを付けた場所への立ち寄り（推定の滞在）
- ラベルを付けた場所は、友人の家などの個人的な場所が多い。タイムラインは、そこでの滞在を記録しないことがある
  - 住所だけの地点（Google マップに場所がなく、placeId の末尾が `AAAAAAAAAAA` のもの）への滞在は、2024 年 1 月を最後に記録されなくなった。その時間は、始まりも終わりも同じ場所の動かない「移動」になっていることがある
  - 滞在が、近くの別の場所（隣の建物など）に付くようになった場所もある
  - 人を拾っただけのような短い立ち寄りは、もともと滞在にならない
- そこで、経路の点と移動の始まり・終わりの位置が、ラベルの場所から 50m（設定 `labelStopM`）以内に来た時間を、短くても「立ち寄り」として滞在に加える（visits の `estimated` = 1。元データの滞在は 0）
  - 近くに来たら始め、200m より遠い点が来るか、点の間が 12 時間あいたら終える。間が 60 分以内の立ち寄りは 1 つにまとめる。点が 1 つだけなら 0 分の立ち寄り
  - 端末は動かないと点を記録しないので、点が 10 分以上途切れたあとに遠い点が来たときは、その遠い点の時刻までそこにいたものとする（例：夜中の最後の点から、翌日に出かけたあとの最初の点まで）。ただし、その間に別の場所（200m より遠く）の本当の滞在が始まっていたら、そこまで
  - 間に別の場所の本当の滞在がある 2 つの立ち寄りは、60 分以内でもまとめない（出かけて戻ってきたため）
  - 移動の始まり・終わりの位置は、前後 10 分の経路の点が 200m より遠くにあれば使わない。長時間動かない移動の終わりの位置が、実際にはもう離れた時刻のものになっていることがあるため
  - その場所の本当の滞在（ラベルから 50m 以内の滞在先）と、前後 15 分の範囲で重なるものは足さない
  - 自宅・職場（訪問 10 回以上）の近くのラベルは使わない（家の前を通るたびに立ち寄りになるため）
  - 滞在先は、ラベルから 30m（設定 `takeoutLabelM`）以内に本当の滞在先があればその場所、なければラベルごとに作る場所（placeId は `label:緯度,経度`。Google の placeId ではないので Google マップのリンクには付けない）。種類は ALIASED_LOCATION、入れ子の階層は 0。時差は、その時刻の前の移動のもの
- 取り込みのたび（Takeout・Swarm も）と「今すぐ照合する」で、地点名の割り当ての前に全部を作り直す（`src/server/labelstops.ts`）
- 推定の滞在も、日付の画面・場所の一覧・訪問回数・集計に、ふつうの滞在と同じように出す。日付の画面・場所の詳細の訪問の一覧・集計の一覧では「推定」の印を付ける
- 場所の集計（places）の座標と種類は、元データの滞在を優先して決める
- 取り込み画面の Takeout の状態に、推定の滞在の数を出す

### Foursquare Swarm（swarm-checkin）
- Swarm アプリの「データのエクスポート」の zip。自分のデータを書き出したものなので、保存してよい
- 使うのはチェックイン（`checkins1.json`, `checkins2.json` …）だけ。店の名前・店の ID と URL・端末の位置（lat・lng と精度 hacc）・時刻（`createdAt`、UTC）・時差（`timeZoneOffset`、分）・ひとこと（`shout`）・イベントの名前がある。店のないもの・位置のないものは使わない
  - 自動で検出された訪問（`unconfirmed_visits.json`）は使わない。チェックインと同じ時刻のものと比べると、店が一致したのは 56% だけだった。`visits.json` には店の名前がない
- **データを入れる**（書き出し直したときだけ）：利用者が取り込み画面の「ファイルを選択」で zip を送る（Takeout と同じ `POST /api/takeout`。Takeout の zip と混ざっていてもよく、チェックインのファイルがある zip を Swarm とみなす。Swarm の zip は 1 回に 1 つまで）。入れたあとすぐ地点への割り当ても行う。管理者はコマンド `server.mjs import-swarm <zip>` でも入れられる
  - zip は残さない。チェックインのファイルだけを `data/users/<利用者名>/swarm/` に置き（毎回全部置き換え。書き出しには毎回全期間が入っている）、そこから DB（`swarm_checkins`）に入れ直し、入れた日時を kv に記録する
- **地点に割り当てる**：Takeout と同じく、取り込みのたびと「今すぐ照合する」で。滞在が変わると割り当ても変わるので、調べる地点があれば全体を付け直す
  - Google のタイムラインと同じ端末で記録しているので、チェックインの時刻を含む滞在先を探し、その場所をチェックインした店とする。時刻を含む滞在先が複数（入れ子の滞在など）あれば、端末の位置にいちばん近いもの（300m 以内）。時刻を含む滞在先がなければ、前後 10 分の滞在先のうち近いもの（150m 以内）
  - 場所ごとに、いちばん多くチェックインした店の名前を付ける（同じ回数なら最後にチェックインした店）。細かい項目に、その店のチェックインの回数・最初と最後の日（その土地の日付）・ひとこと・イベント・Foursquare の URL と、ほかにチェックインした店（同じ建物の別の店など）と回数を持つ。基準点からの距離は、その店のチェックインの位置のうちいちばん近いもの
  - 優先順位は Takeout の保存した場所の次。保存した場所（Google の場所そのものの名前）と同じ場所で比べると、同じ建物の別の店を指していることがあるため
- 場所の詳細に、チェックインの回数と期間・ひとこと・イベント・Foursquare のリンク・ほかにチェックインした店を出す

### 位置参照情報（isj-oaza / isj-gaiku）
- 配布：位置参照情報ダウンロードサービス（国土交通省） https://nlftp.mlit.go.jp/isj/ 。都道府県ごとの zip（中は CSV）。利用条件は公共データ利用規約（PDL1.0）で、出典の表示が必要
- **作業は2つに分かれる**
  1. **位置参照情報を入れる**（zip を持ち込んだときだけ）：`server.mjs import-isj <zip ...>`。地点への割り当てはしない（全国分で約 1 秒）。入れた日時を取得方法ごとに shared_kv（`isj-oaza:loaded_at` / `isj-gaiku:loaded_at`）に記録する
  2. **地点に住所を割り当てる**（タイムラインの取り込みのたび、アプリの中で自動）：まだ調べていない地点と、位置参照情報を入れ直したあとにまだ調べ直していない地点だけを調べる
- 調べたことは、住所が見つからなかった場合も label_checks（placeId＋取得方法＋調べた日時）に記録する。同じ地点を取り込みのたびに探し直さないため
- 配布の zip をファイル名のまま渡す。文字コードは UTF-8 か Shift_JIS を自動で判定し、列は見出しの名前で探す
- **大字・町丁目**（`*-19.0b.zip` など。全国で約19万点）：代表点を areas テーブルに入れる。同じ都道府県を入れ直すと置き換え、ほかの都道府県は残す。近いものを探すときは 0.05 度の格子に分けて、近くのマスだけを調べる
- **街区**（`*-24.0a.zip` など。全国で千万点を超える）：DB には入れず、zip を isjDir（既定は `data/isj`）に置いたまま使う（`import-isj` は置き場所を確かめるだけ）。住所を付けるときに、場所の都道府県（大字・町丁目の住所から分かる）のファイルだけを読む。「更新前履歴フラグ」が 1 の古い記録は使わない
  - 大字・町丁目のデータが入っていて、大字・町丁目の住所が付かなかった場所（海外など）は、街区でも探さない
- 取り込みの結果に、取得方法ごとの「住所が付いた数 / 調べた数」を返す（調べなかった取得方法は出さない）。「このアプリについて」画面には、まだ調べていない地点の数と「今すぐ照合する」ボタンを出す（取り込みのときと同じ処理を、取り込み直さずに行う。取り込みと同時には動かさない）
- 出典は、「このアプリについて」画面と、位置参照情報の住所がある場所の詳細に表示する
- `server.mjs assign-areas` で、すべての場所の住所を付け直せる

### Google Takeout（takeout-label / takeout-saved / takeout-addr / takeout-review / takeout-mymap）
- 自分の Google マップのデータを Takeout で書き出したものなので、保存してよい（Places API の制限は関係ない）
- 使うのは5つ（日本語版・英語版のファイル名に対応）
  - 保存した場所（マップ（マイプレイス）/保存した場所.json）：Takeout の説明でいう「スター付きの場所」。店名・住所・座標・保存日・cid・コメント。座標や名前のないものは使わない
  - クチコミ（マップ（マイプレイス）/クチコミ.json）：自分がクチコミを書いた店。保存した場所と同じ形で、評価（5 段階）と本文が付く
  - マイマップ（マイマップ/*.kmz）：自分で作った地図。kmz の中の KML から地点（名前・フォルダー・メモ・座標）を取り出す。座標は点か、URL（`/maps/search/緯度,経度`）から取り、どちらもなければ座標なしで残す（cid で照らし合わせる）。経路の線・面と、位置のログ（名前が「10:17:23」「#1 10:25:10」のような時刻だけか、説明に経度・緯度があるもの）は除く。メモは決まった項目（メモ・説明）だけを取る（ほかの項目に、書き出した人のメールアドレスなどが入っていることがある）
  - ラベルを付けた場所（マップ/ラベルを付けた場所/ラベル付きの場所.json）：自分で付けた名前・住所・座標
  - 保存リスト（保存済み/*.csv）：リスト名・タイトル・メモ・URL。座標はないので、URL の cid（`!1s0x…:0x…` の後半を 10 進にしたもの、または `cid=`）で保存した場所と照らし合わせる。リストに説明文があると見出しの前に説明の行が入るので、「URL」の列がある行を見出しとする
- **データを入れる**（書き出し直したときだけ）：利用者が取り込み画面の「ファイルを選択」で zip を送る（`POST /api/takeout`。複数の zip はまとめて 1 回で。上限 200MB）。入れたあとすぐ地点への割り当ても行う。管理者はコマンド `server.mjs import-takeout <zip かフォルダー ...>` でも入れられる（同じ処理。割り当ては次の取り込みか「今すぐ照合する」で）
  - zip は残さない。目次を読んでから使うファイルだけを取り出し（写真などは読まない）、`data/users/<利用者名>/takeout/` の `saved/`・`labeled/`・`lists/`・`reviews/`・`mymaps/`（kmz の中の KML）に種類ごとに置く。zip に入っていた種類だけを置き換え、入っていなかった種類は前のまま（書き出しが複数の zip に分かれていて、別々に送られても消えない）。そのフォルダーのファイル全体から DB に入れ直し、入れた日時を kv に記録する。途中で失敗したら、フォルダーも DB も元のまま
- **地点に割り当てる**：位置参照情報と同じく、取り込みのたびと「今すぐ照合する」で
  - 滞在先も保存した場所も Google の「場所」の座標なので、同じ場所ならほぼ一致する（1〜15m 離れると、同じ建物の別の店も混ざる）。そのため保存した場所は「同じ場所」とみなす距離（既定 2m）以内だけを使う。距離を変えたら `assign-areas` で付け直す
  - 住所は「日本、〒…」の大きい順の書式から都道府県以降を取り出す。一部の小さい順の書式（「…, １丁目−１−１ 丸の内 千代田区 東京都 100-0005 日本」）は大きい順に並べ替え、建物名を後ろに添える。海外の住所はそのまま
- 場所の詳細に、保存リスト（タグとして。押すとそのリストで絞り込み）、コメント、保存日、Google マップのリンク（cid）を出す。名前・メモ・タグの検索は、取得方法の細かい項目（保存リストの名前・コメント）にも当たる
- 書き出しの選び方：マップ（「ラベルを付けた場所」だけ）、マップ（マイプレイス）、保存済み。マップの「写真と動画」は容量のほとんどを占めるが使わない

### OpenStreetMap の施設名（osm-poi）
- 公開の Overpass サーバーは混雑で応答しないことが多いので使わず、日本の OSM データを手元に置いて探す
- **データを入れる**（新しくしたいときだけ）：`deploy/make-osm-poi.sh`。Geofabrik の `japan-latest.osm.pbf`（約 2GB）から、osmium-tool で施設のタグ（amenity / shop / tourism / leisure / office / healthcare / craft / historic / aeroway / railway=station,halt / public_transport=station / building）と名前を持つものを取り出し、`osmium export -f geojsonseq`（点と面）にして、`server.mjs import-osm-poi` で osm_pois テーブルに入れる（全部置き換え。面は外周の頂点の平均を代表点にする。名前は name:ja があればそれ）。入れた日時を shared_kv の `osm-poi:loaded_at` に、施設と索引の件数を `osm-poi:counts` に記録する（件数を数えると大きな表を全部読むことになり、ディスクから読むと数秒かかるため。記録がなければ最初に使うときに 1 回だけ数える）
- **地点に割り当てる**：位置参照情報と同じく、タイムラインの取り込みのたびと「今すぐ照合する」で、まだ調べていない地点（とデータを入れ直したあとに調べ直していない地点）だけ。60m 以内の施設から「距離＋種類による上乗せ」がいちばん小さいものを選ぶ（上乗せ：店や施設 0m、駅・空港 15m、建物 25m、それ以外 40m。店に行ったのに隣の駅や建物の名前が選ばれないように）
- 日本の外の地点には付かない

### OpenStreetMap の住所（osm-addr）
- サーバーの cron で毎時 `deploy/fetch-osm.sh`（`server.mjs fetch-osm --limit 150`）を起動し、まだ調べていない地点を**よく行く順**に最大 150 か所、Nominatim の逆ジオコーディング（layer=address）で取って貯める。海外の地点にも付く
- 日本は大きい順に区切りなしでつなげ、後ろの項目に含まれる項目（「丸の内」と「丸の内一丁目」）は省く。都道府県の項目がないとき（東京都など）は ISO 3166-2 のコードから補う。海外は Nominatim の表記から施設名と郵便番号を除いたもの
- 公開サーバーの利用規約を守る：問い合わせは 15〜25 秒に1回（1日以上かけて動かすなら 1分 4 件まで。下限 15 秒はコマンドの指定でも下げられない）、並列にしない（ロックファイル `data/osm.lock`。2時間以上前のものは残骸とみなす）、識別できる User-Agent（設定 `osmUserAgent`）、結果を保存する
- 429 / 403 / 503 / 509 などが返ったら、その回はすぐ止める。通信エラーの原因（cause・個々の宛先）もログに出す
- IPv6 で外に出られない環境でもつながるよう、fetch-osm / osm-lookup のときだけ IPv4 を先に試し、1つの宛先を 2.5 秒まで待つ（Node の既定の 250 ミリ秒では海外のサーバーに繋がる前に打ち切られていた）
- ログに開始（今回の件数・未調査の総数・間隔）・10 か所ごとの進み具合・終了（かかった時間・結果）を出す。結果を出す前にプロセスが終わったときも、何か所目まで進んだかを出す
- 1回の取得に約 50 分。最後の実行の結果は kv の `osm:last_run`
- 動作確認用に `server.mjs osm-lookup <緯度> <経度>`（1地点だけ問い合わせて表示。保存しない）

- 「このアプリについて」画面に、施設のデータの件数と入れた日、施設名の付いた地点の数、住所の進み具合を出す

## タグ（ハッシュタグ）
- タグは「#ほげほげ」の形で扱う。保存するときは先頭の #（全角の ＃ も）を外し、空白は _ にそろえる（ハッシュタグは空白を含められないため）
- 入力：名前・メモ・タグの入力欄に「#ラーメン #出張」のように書く（空白・カンマ・読点で区切る。# を付け忘れた語もタグにする）
- 表示：「#タグ」。Google Takeout の保存リストの名前もタグとして出す（空白は _ に。例：#デフォルト_リスト）。押すとそのタグで絞り込んだ場所の一覧へ
- 検索（場所の一覧・集計）：検索語のうち「#タグ」は、自分で付けたタグか Takeout の保存リストの名前に**ぴったり一致**するもの。それ以外の語は、名前・メモ・タグ・住所・地点名など（取得方法の細かい項目も含む）の一部に当たるもの。両方あれば両方を満たすもの（例：「渋谷 #ラーメン」）
- 書き出しの CSV のタグの列も「#タグ」を空白区切りで並べる

### まとめてタグ付け（場所の一覧）
- 場所の一覧の「まとめてタグ付け…」で開く。いまの絞り込み条件に合う場所を**全部**（最大 1,000 か所）、詰めた一覧で並べる。1,000 か所を超えたら操作できず、絞り込むよう案内する（見えていない場所に黙って付けないため）
- チェックは「そのタグが（自分のタグとして）付いているべきか」を表す。タグ（#レストラン など）を入れると、いま自分のタグで付いている場所にだけチェックが入る（初めて使うタグなら全部オフ）。タグを入れるまではチェックできない
- 「すべて選択／すべて解除」と個別のチェックで、付いているべき状態にしてから「適用」を押すと、それを DB に反映する（チェックが入った場所には付け、外した場所からは外す）。反映するのは初めの状態から変えた場所だけで、ボタンに件数を出す（「適用（追加 2・解除 1）」）。変えた行には「追加」「解除」の印を出す。「元に戻す」で、直前の適用を反対向きに戻せる
- Takeout の保存リストで付いている場所には、その旨を出す（チェックは自分のタグについてだけ）
- 地図のピンは、チェックが入っている場所を青、入っていない場所を灰色にする
- 行を押すと、その場所に地図を寄せて拡大し（ズーム 17）、吹き出しを出す（地図上の店名などで、除外するかどうかを確かめられる）。押した行は強調する。チェックの切り替えは、チェックボックスと地点名を押したときだけ（このときは地図を動かさない）
- 吹き出しの「この場所の記録」で詳細を開き「戻る」で戻ると、まとめてタグ付けの続きになる（タグ、決定前のチェック、押していた行、地図の位置、「元に戻す」）。開いていることは URL（`bulk=1`）に残す。ページを読み込み直したときは、開いた状態だけが戻る
- まとめてタグ付けの間は、地図を動かしても「地図の表示範囲内のみ」の条件を変えない（拡大した途端に一覧が絞られないように）
- チェックを切り替えたときは、ピンを作り直さず色だけを変える。全体が入る縮尺に合わせ直すのは、並ぶ場所の顔ぶれが変わったときだけ（拡大して見ている位置が、チェックやタグの付け直しで戻らないように）
- 実行すると「#浴場 を〇か所に追加しました」と出し、「元に戻す」を一度だけ出す（今回変わった場所だけを元に戻す）。実行後は選択を空にする
- API：`POST /api/places/tags`（`{placeIds, add, remove}`。名前とメモはそのままでタグだけを変え、実際に変わった場所の placeId を返す。名前もメモもタグも空になったノートは消す）。場所の一覧の API に `checkTag` を付けると、各場所のそのタグの状態（`tagState`）を返す

## 画面

URL の `#` 以降で画面を切り替える。

| URL | 画面 |
|---|---|
| `#/day/YYYY-MM-DD` | 日付から見る（日付を省くと、データがある最後の日） |
| `#/places?q=…&kind=…&from=…&to=…&sort=…&area=0` | 場所から見る（一覧）。既定でない条件だけ URL に残す（`area=0` は「地図の表示範囲内のみ」を OFF にしたとき） |
| `#/place/{placeId}` | 場所の詳細 |
| `#/search?target=…&from=…&to=…&weekdays=…&q=…&kind=…&modes=…&group=…&measure=…` | 集計。条件は URL に残す |
| `#/trips?from=…&to=…&sort=…` | 旅行の一覧 |
| `#/trip/{開始時刻ms}` | 旅行の詳細（旅行は取り込みのたびに作り直されて id が変わるので、開始時刻で指す） |
| `#/lists?list=…&f=…` | 保存リスト |
| `#/user` | ユーザー情報：アイコン、データの取り込みへのリンク、パスワードの変更、ログアウト（見出しのメニューの利用者名から） |
| `#/import` | データの取り込み（ユーザー情報からリンク。上に「‹ ユーザー情報」）。欄は「ファイルのインポート」「タイムライン」「ユーザーデータ（名前・メモ・タグ・ブックマーク）」「地点名・住所（Google Takeout）」「地点名（Foursquare Swarm）」「インポート履歴」の順。「ユーザーデータ（名前・メモ・タグ・ブックマーク）」の欄（数、「エクスポート（JSON）」）。書き出したファイルは「ファイルのインポート」（と共有）から送ると、先頭の印（`"format": "gtexp-userdata"`）で見分けて読み込む。「タイムライン」「Google Takeout」「Foursquare Swarm」と、ユーザーデータの欄の末尾に「削除」（データがあるときだけ。押すと「本当に削除しますか？」と消えるものの説明を出し、もう一度「削除」で消す）。タイムラインのデータがまだないときは、ログインした後や最初の画面（日付）を開いたときに、ここを開く |
| `#/bookmarks` | ブックマークの一覧（見出しの右端のメニューと、☆ の欄からリンク） |
| `#/about` | このアプリについて（ログインしていなくても見られる。ログインしているときは「ライセンスと表示」の前に「住所・施設名のデータ」として、サーバーの管理者が入れる「住所データベース（位置参照情報）」「施設名・住所（OpenStreetMap）」の欄を出す（取り込みの画面から移した。調べた地点の数と「今すぐ照合する」は利用者ごと）。ログインの画面と、見出しの右端のメニューからリンク）。版・著作権・プロジェクトの URL、画面とサーバーそれぞれのビルドのコミットと日時（違っていれば読み込み直しを勧める）、NOTICE の全文（ビルドのときに埋め込む）と LICENSE へのリンク |
| （未ログイン時） | ログイン |

期間の指定（場所・集計・旅行で共通）：年を選ぶか、始めと終わりの日付を入れる。ドロップダウンは「全期間」と年。日付で指定しているときは、いちばん上に選べない「期間」を出す（「全期間」を選ぶと解除する）。始めを終わりより後にしたときは終わりを、終わりを始めより前にしたときは始めを、同じ日にそろえる。

時間の長さは、1 時間未満は「45分」、日の単位になるまでは「3時間20分」（合計は「30時間」）、日の単位では時間が 0 でも省かずに「5日 0時間」と出す（一つの滞在は 24 時間以上、合計は 48 時間以上で日の単位）。

見出しのタブの「場所」「集計」「旅行」「保存リスト」は、最後に開いていたその一覧の URL（絞り込みの条件付き）へ移る。ほかの画面へ移ってから戻っても、同じ条件で開く（覚えるのは画面を読み込み直すまで）。その一覧を開いているときに押しても何もしない。詳細（場所・旅行）から押すと一覧に戻る

### 日付から見る
- 前の日 / 次の日 / 日付入力 / 今日
- 月のカレンダー：滞在の多い日ほど濃く塗る（0 / 1〜2 / 3〜5 / 6〜9 / 10 件以上）。月・年の移動、月の合計（滞在件数・移動距離）。スマホ幅では最初は畳む
- その日の滞在と移動を時刻順に並べる
  - 滞在：番号、時刻（別の日にまたがるときは日付も）、滞在時間、名前（自分で付けた名前 → 自宅・職場などの種類 → 「名前なし」の順）、座標、通算の訪問回数
  - 入れ子の滞在（hierarchyLevel 1 以上）は、主な滞在の下に字下げして小さく出す。番号は主な滞在だけ
  - ラベルを付けた場所への推定の立ち寄り（元データにない滞在）には「推定」の印を付ける
  - 移動：手段のアイコンと名前、距離、時刻、所要時間
  - 記録なし：滞在にも移動にも入っていない 10 分以上の時間を「記録なし」として、時刻と長さを出す（集計の「記録なし」と同じ決め方）
  - 旅行中の日は、旅行の期間と出発地からの距離を表示し、その旅行の詳細へリンク
- 各滞在から Google マップ / Google Earth で開く。名前・メモ・タグを付けられる（同じ placeId のすべての記録に付く）
- 滞在の名前を押すと、その場所の詳細へ
- 地図：番号付きのピン（自宅は緑、職場は青、その他は赤、入れ子は小さい灰色）、経路の線、経路の点がない移動は始点と終点を点線で結ぶ（飛行機は大円）。全体が入るように縮尺を合わせる（最大ズーム 17）。ピンかリストを選ぶと吹き出しを出す
- 地図の API キーが未設定なら、地図の代わりに案内を出す（ほかは動く）

### 場所から見る（一覧）
- 場所ごとに訪問を集計して並べる。並べ替え：訪問回数が多い順（既定）/ 最終訪問が新しい順 / 初回訪問が古い順 / 滞在時間が長い順
- 絞り込み
  - 名前・メモ・タグの文字列（打ち終わって 0.3 秒後に反映）
  - 種類：すべて / 自宅 / 職場 / 名前登録済み / 名前未設定
  - 期間：年を選ぶか、開始日・終了日を指定。期間を指定すると、回数や最初・最後の日はその期間の中で数える
  - 地図の表示範囲内のみ（既定は ON）：地図を動かし終わるたびに範囲で再検索する。地図を出せない（API キーがない・キーが断られた）ときは OFF として全体を出す
    - 地図の最初の位置：位置情報がすでに許可されていれば現在地の付近、そうでなければ記録のある場所の大部分（訪問の回数で重みを付け、南北・東西の端の 5% ずつを除いた範囲。`GET /api/places/extent`）、記録もなければ東京駅付近。詳細から戻ったときは、前に見ていた位置
- 一覧は 100 件ずつ（「もっと見る」で続きを読む）。各行に順位、名前、種類、タグ、回数、最後に行った日、滞在時間の合計
- 地図には上位 300 か所までピンを出す（上位 99 は順位の数字入り、上位 10 は大きめ）。ピンか一覧を選ぶと吹き出し（詳細へのリンク、Google マップ / Earth）
- 最後に見ていた地図の位置を覚えておき、詳細から戻ったときに復元する。条件も URL から復元する
- タグを押すと、そのタグで絞り込んだ一覧へ

### 場所の詳細
- 名前（なければ自宅などの種類、それもなければ「名前なし」）、タグ、メモ、Google マップ / Earth、名前・メモ・タグの編集
- 訪問回数、初めて / 最後に行った日（日付の画面へのリンク）、滞在時間の合計
- 折り畳み「訪問回数（N回）」（最初は開く）：その中に年ごとの折り畳み「2026年（3回）」を新しい年から並べ（最初はいちばん新しい年だけ開く）、それぞれに訪問の一覧を新しい順に（各日付は日付の画面へのリンク。入れ子の滞在には、その時間を含む外側の滞在の場所を「（○○内）」と添え、その場所の詳細へリンクする。外側が見つからなければ「（施設内）」）
- 折り畳み「詳細」（最初は閉じる）：取得方法ごとの地点名・住所（見つからなかった・まだ調べていないものも）、位置、位置参照情報・OpenStreetMap の出典
- 地図にその場所のピン

### 集計
- 対象：滞在 / 移動 / 出発 / 到着 / 記録なし
  - 記録なし：滞在（入れ子も含む）にも移動にも入っていない時間。10 分未満の隙間（前後の記録のつなぎ目）と、最初の記録より前・最後に取り込んだ記録より後は含めない。時刻は直前の記録の時差で表す
  - 記録なしでは、場所・移動手段の条件と書き出しは出さない。回数は始まった日が期間・曜日に入る空白の数、日数は空白が少しでもかかった日の数、時間は滞在と同じく切れ目で切り分けて数える。まとめ方は年・月・曜日・時間帯。記録の一覧は空白を新しい順に出し、日付からその日の画面へ移る
  - 出発：主な滞在を終えて移動を始めたとき（滞在の終わりの前後 10 分以内に移動が始まる）。到着：移動を終えて主な滞在を始めたとき（移動の終わりが滞在の始まりの前後 10 分以内）。移動どうしの乗り換えと、推定の立ち寄りは数えない
  - 出発・到着では、場所の条件（名前・メモ・タグ、種類）を、出発では出た場所、到着では着いた場所に当てはめる（種類を自宅にすると「家を出た」「家に帰った」）。期間・曜日・まとめ方（年・月・曜日・時間帯）は、出発（到着）した現地時刻で決める。数えるのは回数と日数だけ（時間・距離・書き出しはなし）
  - 出発・到着の一覧：新しい順に、時刻と「〇〇を出発 → 行き先（🚆 45分）」「〇〇に到着 ← 来た場所から」。行き先（来た場所）は 1 日以内の次（前）の主な滞在、手段は間の移動のうち距離のいちばん長いもの
- 条件：期間（年を選ぶか日付で指定）、曜日（複数選べる。選ばなければすべて）。滞在は名前・メモ・タグと種類、移動は移動手段（複数選べる）
- 滞在は、場所の条件（名前・メモ・タグ、種類）がなければ主な滞在だけを数える（入れ子まで数えると時間が二重になるため）。場所で絞ったときは入れ子も含める
- 合計：件数（回数）、日数、時間、距離（移動だけ）
  - 件数・日数・距離は、始まった日で数える。時間は、期間にかかる滞在（移動）を現地時刻の日（時間帯ごとのときは時）の切れ目で切り分け、期間・曜日に入る部分だけを、まとめ方の区切りごとに足す。重なった時間は 1 回だけ数える（移動手段ごとのときは手段ごとに）。始まった月にまとめると、月をまたぐ滞在や重なりで月の日数を超えることがあったため
- まとめ方：年ごと / 月ごと / 曜日ごと / 時間帯ごと（開始時刻）/ 移動手段ごと（移動だけ）。値は件数 / 日数 / 時間 / 距離から選ぶ
  - 年・月・曜日・時間帯は縦棒グラフ。記録のない区切りも 0 で並べる。年の棒を押すと、その年の月ごとに切り替わる
  - 移動手段ごとは横棒（値の大きい順）
  - 「表で見る」で、区切りごとの件数・日数・時間・距離の表
- 記録の一覧（新しい順、100 件ずつ）。日付は日付の画面へ、場所の名前は場所の詳細へのリンク
- 日数は、記録の開始日で数える。時間は記録ごとの長さの合計（日をまたぐ滞在は開始日の側に入る）

### 書き出し
- 集計の画面（記録の見出しの下）と場所の一覧（件数の下）に「CSV / KML / GPX / GeoJSON」のリンク。いまの条件に合うものを**全件**書き出す（一覧の 100 件ずつの区切りは関係ない）
- 中身

| 対象 | CSV | KML / GPX / GeoJSON |
|---|---|---|
| 滞在 | 日付・開始・終了・滞在（分）・名前・種類・メモ・タグ・入れ子・緯度・経度・placeId・Google マップの URL | 点（KML は TimeSpan 付き、GPX は wpt） |
| 移動 | 日付・開始・終了・時間（分）・移動手段・距離（km）・出発と到着の緯度経度 | 線：始点 → その時間帯の経路の点 → 終点（GPX は trk） |
| 場所 | 名前・種類・訪問回数・初めて・最後・滞在の合計（時間）・メモ・タグ・緯度・経度・placeId・Google マップの URL | 点（GPX は wpt） |

- CSV は Excel で文字化けしないよう UTF-8 の BOM 付き、改行は CRLF
- 名前は、自分で付けた名前 → 自宅などの種類 → 「名前なし」の順
- 経路の点は Google 側で記録されていない時間帯も多い。ない場合は始点と終点を結ぶだけ
- ファイル名：`gtexp-{visits|activities|places}[-開始日-終了日].{csv|kml|gpx|geojson}`

### 旅行の一覧
- Google が「旅行」としてまとめた記録（timelineMemory）。期間で絞り込み（期間に少しでもかかる旅行）、並べ替え：新しい順 / 日数が長い順 / 出発地から遠い順
- 全期間のときは、年ごとの旅行の日数の棒グラフ（旅行の始まった年で数える。棒を押すとその年だけに）
- 各旅行：期間と日数、出発地からの距離、滞在の数、移動距離、行き先（名前を付けていれば名前、なければ「行き先 n か所」）

### 旅行の詳細
- 日数、出発地からの距離、滞在の数（主な滞在）、移動の数と距離
- 書き出しリンク（滞在 / 移動）。集計の書き出しを、旅行の最初の日から最後の日までの期間で使う
- 行き先：Google マップで開く（placeId だけで開く `https://www.google.com/maps/place/?q=place_id:…`）、名前を付ける
  - 行き先は地域を指す placeId で、滞在の記録とは重ならない。名前も座標も分からないので、Google マップで確かめて自分で名前を付ける（場所の名前と同じ place_notes に保存）
- 日ごと：日付（日付の画面へ）、滞在の数、移動距離
- 滞在先の一覧（時刻順）。始まった日ごとの折り畳み（「5/3（土）（8件）」のように件数付き。最初はすべて開く）に分ける。場所の詳細へリンク。地図でピンを選ぶと、その日が閉じていれば開く
- 地図：旅行中の経路（5,000 点を超えたら間引く）と滞在先のピン

### 保存リスト
- Takeout の保存リストとマイマップを見るタブ。タイムラインのデータは読むだけで変えない
- リストを選ぶと、店を一覧と地図に出す。選ぶ欄は「保存リスト」「マイマップ」に分ける（URL の `list` は、マイマップなら「mymap:地図の名前」）。絞り込み「すべて／訪問履歴あり／訪問履歴なし」（それぞれの数も出す）
- マイマップの地点は、点の座標があればそれを使う。タイムラインにあるかは、その位置から `takeoutNearM`（30m）以内のいちばん近い滞在先で決める（cid があり、その店に地点名が付いていればその滞在先）。フォルダーの名前をコメントの欄に出す
- 保存リストの CSV には座標がない（店名・メモ・URL だけ）ので、店の位置は次の順に探す（座標のないマイマップの地点も同じ）
  1. Takeout の「保存した場所」「クチコミ」「マイマップ」に同じ店（cid）があれば、その座標
  2. 地図に落としたピンなら、URL（`/maps/search/緯度,経度`）の座標
  3. 店名を OSM の施設の名前と照らし合わせる（全角・半角、空白・記号、末尾の「店」の有無をそろえて完全一致。括弧の中の別名を除いた名前でも探す）。同じ名前の施設が 300m より離れて複数あれば、どれか決めない（「位置不明（OSM に同じ名前が n か所）」）
- タイムラインにあるかは、1 なら地点名の割り当て（takeout-saved の cid）、2・3 ならその位置から `takeoutNearM`（30m）以内のいちばん近い滞在先で決める
- 一覧の各行：店名、「n 回・最終 日付」か「訪問履歴なし」、位置の出どころ（OpenStreetMap から推定・地図のピン・位置不明）、メモとコメント、「この場所の記録」（タイムラインにある店）、「Google マップ」
- 地図：タイムラインにある店は青、ない店は橙のピン。OSM の名前から推定した位置は「?」を出す。行を押すと寄せて拡大し、吹き出しを出す（位置不明の行は押しても動かない）。ピンは 2,000 か所まで
- 「この場所の記録」から戻ると、リスト・絞り込み（URL の `list`・`f`）、一覧の位置、地図の位置が元のまま
- OSM のチェーン店は、名前にチェーン名だけが入っていて支店名がないものが多く、名前では見つからないことがある。支店名が `branch` タグに分かれているものは、施設を入れるときに名前につなげる

### 取り込み
- 利用者が入れるデータ（自分のタイムラインのエクスポートと Google Takeout・Foursquare Swarm の書き出し）は、この画面の「ファイルを選択」で送る。管理者が入れるデータ（位置参照情報・OpenStreetMap）は、「このアプリについて」画面で状態と出典だけを出し、入れかたは管理者向けの文書（`deploy/README.md`。画面からは GitHub の設置手順へリンク）に書く
- 「タイムライン」の欄：いま入っているデータの概要（期間、滞在・場所・移動・経路の点・旅行の件数）
- 「ファイルを選択」は複数選べる。.zip は Google Takeout か Swarm としてまとめて 1 回で送り（`POST /api/takeout`。どちらかはサーバーが中身で決める）、それ以外はタイムラインのエクスポートとして 1 つずつ送る（`POST /api/import`）。素の JSON はブラウザで gzip 圧縮してから送る（10 分の 1 ほどになる）。圧縮中 / 送信中（進捗）/ 取り込み中 を表示
- タイムラインのエクスポートのしかた（Android）と、Google Takeout・Foursquare Swarm の書き出しかたを、折りたたみで出す
- Android の「共有」から受け取ったファイル（.json / .gz / .zip）は、Service Worker が Cache Storage に置き、データの取り込みの画面（`#/import?shared=1`）が取り出して送る
- 位置参照情報・Google Takeout・Foursquare Swarm・OpenStreetMap の状態（件数、名前や住所が付いた地点の数）。まだ調べていない地点があれば「今すぐ照合する」
- インポート履歴（新しい 20 件ずつ。「もっと見る」で続き）：日時、取り込んだもの（タイムライン・Google Takeout・Foursquare Swarm・ユーザーデータと、ファイル名）、内容（タイムラインは期間と滞在・移動の件数、Takeout は zip に入っていて置き換えた種類ごとの件数、Swarm はチェックインと店の数、ユーザーデータは読み込んだ数）

### ブックマーク
- どの画面でも、見出しの右端の ☆ を押すと「ブックマークに追加」の欄を出す。名前を決めて「追加」で、その画面の URL（`#` 以降。絞り込みの条件を含む）をブックマークに足す。足した画面では ★ になる
- ★ を押すと「ブックマークの解除」の欄（名前を出す）。「解除」で外す
- どちらも「キャンセル」・外を押す・Esc・画面の切り替えでは何もせずに閉じる。名前を変えるのはブックマークの一覧で
- 名前の既定は画面の名前（ブラウザのタブの名前と同じ）：日付（2024年5月25日（土））、場所の名前、場所「検索語」期間、集計「検索語」期間、旅行 期間、保存リスト「リスト名」など。あとで変えられる（200 文字まで）
- 同じ URL は 1 つだけ（足し直すと名前だけ変わる）。絞り込みを変えると URL が変わるので、☆ に戻る
- ブックマークの一覧（`#/bookmarks`）：並べた順（足したものはいちばん上）。名前を押すとその画面に飛ぶ。画面の種類と足した日、名前を変更・削除。6 件以上あれば名前で絞り込める
- 並べ替え：左のつまみ（点 6 つ）をつかんで動かす（マウスでも指でも）。離したときに保存する。名前で絞り込んでいる間はつまみを出さない。キーボードでの操作は付けない（ほかの画面にもキーボードの操作はない。つまみは Tab キーで止まらない）
- 利用者ごとの DB に持つ（ほかの端末でも同じものが出る）

### 現在地（すべての地図）
- 地図の右下に「現在地」ボタン（端末が位置情報に対応しているとき）。押すと端末の位置（GPS など）を取り、地図を寄せて（ズーム 16 まで）青い点と精度の円を出す
- 一度押したあとは、位置が変わるたびに点を動かす（地図は動かさない。もう一度押すと寄せ直す）。地図の画面を離れたら追うのをやめる
- 位置情報が許可されていないときは、その旨を地図の上に出す。追っている途中の一時的な失敗は知らせない
- 位置情報は端末の中だけで使い、サーバーには送らない（ブラウザの位置情報は HTTPS でしか使えない）

### 外部リンク
- Google マップ：`https://www.google.com/maps/search/?api=1&query=緯度,経度&query_place_id=placeId`（非公開の placeId は付けない）
- Google Earth：`https://earth.google.com/web/search/緯度,経度`

## API
ログイン関係（`/api/login`、`/api/logout`、`/api/me`）と `/api/health` 以外はログインが必要（Cookie `gtexp_session`）。ログインした利用者の記録だけを扱う（ほかの利用者の記録には届かない）。

| メソッドとパス | 内容 |
|---|---|
| `POST /api/login` | `{user, password}` → Cookie を発行し `{loggedIn, user}` を返す。利用者名は大文字・小文字を区別しない（小文字にそろえる）。2 段階認証がオンなら、ログインの Cookie は渡さず、5 分だけ有効な確認待ちの Cookie（`gtexp_mfa`。`/api/login` の下にだけ送られる）と `{loggedIn: false, mfaRequired: true}` を返す |
| `POST /api/login/mfa` | `{code}`（認証アプリの 6 桁かバックアップコード）。確認待ちの Cookie とコードを確かめて、ログインの Cookie を発行する。間違いはログインの失敗と同じに数える |
| `POST /api/logout` | Cookie を消す |
| `GET /api/me` | `{loggedIn, user, icon, mfa, recoveryLeft}`（icon はアイコンの版。未設定なら null。mfa は 2 段階認証を使っているか、recoveryLeft は残っているバックアップコードの数） |
| `GET /api/me/icon?v=…` | アイコンの画像（PNG・JPEG・WebP）。未設定なら 404 |

| `GET /api/userdata` | 自分で付けた名前・メモ・タグとブックマークを JSON で書き出す（`gtexp-userdata-<利用者名>-YYYYMMDD.json` として保存させる）。`{format: "gtexp-userdata", version: 1, exportedAt, notes: [{placeId, name, memo, tags, updatedAt}], bookmarks: [{hash, title, createdAt}]}`（ブックマークは並べた順） |

| `POST /api/me/mfa/setup` | 2 段階認証の設定を始める。新しい鍵を作り（確認のコードが通るまでは有効にしない）、`{uri, secret}`（`otpauth://` の URI と Base32 の鍵）を返す |
| `POST /api/me/mfa/enable` | `{code}`。設定中の鍵のコードが合えば有効にし、バックアップコード 10 個を返す（この 1 回だけ）。ほかの端末はログアウトされ、この端末には新しい Cookie を返す |
| `POST /api/me/mfa/disable` | `{password, code}`。パスワードとコードを確かめて無効にする |
| `POST /api/me/mfa/recovery` | `{code}`。コードを確かめて、バックアップコードを再発行する（前のものは使えなくなる） |
| `POST /api/me/password` | `{current, next, code}`。今のパスワード（2 段階認証がオンならコードも）を確かめて（間違いはログインの失敗と同じに数える）、新しいパスワード（8 文字以上）にする。ほかの端末はログアウトされ、この端末には新しい Cookie を返す |

### 日付の区切り
1日は設定の `tzOffsetMinutes`（日本は 540）で区切る。カレンダーの集計は、各記録の開始時刻の文字列から取った日付（`local_date`）を使う。

## 利用者
- 利用者どうしは独立していて、共有はしない。記録は利用者ごとの DB（`data/users/<利用者名>/gtexp.sqlite`）と、取り込んだ元ファイル（`data/users/<利用者名>/imports/`）に持つ
- 全員で使うのは、参照データ（位置参照情報・OSM の施設）と利用者の一覧で、`data/shared.sqlite` に置く。利用者の DB を開くときに `shared` として ATTACH する。利用者の DB には同じ名前のテーブルを作らないので、SQL はテーブル名だけで shared の方に届く（あると開くときに止める）
- 利用者の一覧（`users`）：名前、scrypt のパスワードのハッシュ、session_key。名前は英小文字・数字・`_`・`-`（32 文字まで）。管理はコマンドだけ（user-add / user-passwd / user-del / user-list）
- ログインの Cookie は「利用者名.有効期限.署名」。署名には設定の sessionSecret と利用者の session_key を混ぜる。パスワードを変えると session_key を作り直すので、その利用者のログイン中の端末はログアウトされる。利用者を消してもログインできなくなる
- 2 段階認証（TOTP、RFC 6238。Google Authenticator などの認証アプリ）：利用者ごとに任意（最初はオフ）。30 秒ごとの 6 桁で、端末とサーバーの時計のずれは前後 30 秒まで受け付ける。同じコードは 2 回使えない（最後に使った時刻の区切りを覚える）
  - 鍵は設定の sessionSecret から作った鍵（AES-256-GCM）で暗号化して `user_mfa` に持つ。sessionSecret を変えると読めなくなるので、管理者が `user-mfa-reset` で外し、利用者が設定し直す
  - バックアップコード（`xxxx-xxxx` を 10 個。1 つ 1 回）は、有効にしたときと再発行したときに 1 回だけ渡し、ハッシュだけを持つ。ログインの確認コード・パスワードの変更・再発行・無効にするときのコードの代わりに使える
  - コードを聞くのはログインのときだけで、そのあとはログアウトするかログインの期限（sessionDays）まで聞かない（「この端末を覚える」は作らない）。パスワードの変更と無効にするときも、コードを確かめる。有効にすると、ほかの端末はログアウトされる
  - 設定はユーザー情報の画面の「2 段階認証」：「2 段階認証を設定」で QR コード（qrcode-generator。設定を始めたときだけ読み込む）、「認証アプリで開く」（`otpauth://` のリンク。スマホ 1 台で登録するとき）、キーの文字列（「コピー」付き）を出し、アプリの 6 桁を入れて「有効にする」。有効にしたらバックアップコードを表示する（コピーできる）。オンのときは「バックアップコードを再発行」「無効にする」
  - ログインの画面：パスワードのあと、2 段階認証がオンなら「確認コード」の入力に切り替える（バックアップコードも入れられる。「パスワード入力に戻る」でやり直す）
  - `check` は、2 段階認証を使っている利用者がいれば、時刻を合わせる仕組み（ntpd・chronyd など）が動いているかを確かめる
- 見出しの右端のメニュー（≡）に、上から利用者のアイコンと名前（押すとユーザー情報）、（区切り線）「ブックマーク」、（区切り線）「gtexpについて」（[Title] ShortText を使う。画面は「このアプリについて」）・「再読み込み」を置く（画面を切り替えるタブとは分ける。外を押す・Esc・画面の切り替えで閉じる）。「再読み込み」は画面を読み込み直す（スマホの PWA では、地図のある画面で下に引っ張って読み込み直すのがしにくいため）
- ユーザー情報（`#/user`）：
  - アイコン：画像を選ぶと、画面の側で中央を正方形に切り抜き、512×512 ピクセルより大きければ縮めて（小さければそのまま）、WebP（書けないブラウザーは PNG）で送る。サーバーは `data/users/<利用者名>/icon` に置く。未設定のときと読み込めないときは、初期のアイコン（人の形）を出す。メニューの利用者名の左にも出す
  - データの取り込み：別の画面（`#/import`）のまま、ここからリンクで移る（見出しのタブの「取り込み」はやめた）
  - パスワードの変更：今のパスワードと、新しいパスワード（8 文字以上）を 2 回
  - ログアウト：メニューから移した
- 画面は、ログアウトのときに読み込み直す（前の利用者の地図の位置や作業中のタグ付けを残さないため）。ログイン画面には、最後にログインした利用者名を入れておく
- 参照データを入れた日時（`isj-oaza`・`isj-gaiku`・`osm-poi` の loaded_at）と OSM の施設の件数（`osm-poi:counts`）は `shared_kv` に、ほか（Takeout の loaded_at、osm:last_run など）は利用者の `kv` に持つ。参照データを入れ直すと、利用者それぞれが次の取り込みで調べ直す
- fetch-osm は、Nominatim の問い合わせの間隔をサーバー全体で守るため、全員の分を 1 回 150 件の中で、利用者を順に回しながら取る（結果は利用者ごと）

## データベース（SQLite）
利用者ごとの `data/users/<利用者名>/gtexp.sqlite` と、全員で使う `data/shared.sqlite`。テーブル定義は `src/server/db.ts`。

| テーブル | 中身 | 取り込みで |
|---|---|---|
| `visits` | 滞在（`estimated` が 1 のものは、ラベルを付けた場所への推定の立ち寄り） | 置き換え（推定の分は割り当てのたびに作り直す） |
| `activities` | 移動 | 置き換え |
| `path_points` | 経路の点（時刻・緯度・経度で重複を除く） | 置き換え |
| `trips` | 旅行 | 置き換え |
| `places` | 場所ごとの集計（訪問回数、最初と最後の日、最後の座標と種類） | visits から作り直す |
| `place_labels` | 場所の住所・地点名（取得方法ごとに1件） | 新しい場所に住所を足す |
| `areas` | 位置参照情報の代表点（shared） | 触らない（`import-isj` で入れる） |
| `takeout_places` | Takeout の保存した場所・ラベルを付けた場所・クチコミ | 触らない（`POST /api/takeout` か `import-takeout` で入れる） |
| `takeout_lists` | Takeout の保存リスト | 触らない（`POST /api/takeout` か `import-takeout` で入れる） |
| `takeout_mymaps` | Takeout のマイマップの地点 | 触らない（`POST /api/takeout` か `import-takeout` で入れる） |
| `swarm_checkins` | Foursquare Swarm のチェックイン | 触らない（`POST /api/takeout` か `import-swarm` で入れる） |
| `osm_pois` | OSM の名前の付いた施設（shared） | 触らない（`import-osm-poi` で入れる） |
| `osm_poi_keys` | OSM の施設を名前で探す索引（保存リストの店の位置を探す。shared） | 触らない（`import-osm-poi`・`osm-poi-keys` で作る） |
| `label_checks` | 地点の住所を取得方法ごとに調べた日時 | まだ調べていない地点などを調べて記録 |
| `place_notes` | 自分で付けた名前・メモ・タグ | **触らない** |
| `bookmarks` | ブックマーク（画面の URL・名前・並び順 position） | **触らない** |
| `imports` | 取り込みの履歴（kind・detail。タイムライン以外は件数の列が 0）。データを削除すると、その種類の行も消える | 追加 |
| `kv` | userLocationProfile など | 上書き |
| `users` | 利用者の一覧（shared） | 触らない（コマンドで管理） |
| `user_mfa` | 2 段階認証の鍵（暗号化）・設定中の鍵・最後に使ったコードの区切り・バックアップコードのハッシュ（shared） | 触らない（`user-mfa-reset` で外す） |
| `shared_kv` | 参照データを入れた日時と件数（shared） | 触らない |

### 取り込みの規則
1. ファイルの全セグメントから最初の開始時刻を求める
2. それ以降の visits / activities / trips / path_points を削除する
3. ファイルの内容を入れる（1トランザクション）
4. places を作り直し、userLocationProfile を保存し、履歴を残す

元ファイルは `data/users/<利用者名>/imports/日時_ファイル名.gz` に保存する。rawSignals は今のところ取り込まない。

## コマンド（server.mjs）

`node dist/server.mjs <コマンド>` のように、展開したフォルダーで実行する。

利用者の記録を扱うコマンド（`import`・`import-takeout`・`import-swarm`・`assign-areas`）は `--user <名前>` で利用者を選ぶ。利用者が 1 人だけなら省ける。

| コマンド | 内容 |
|---|---|
| `serve` | サーバーを起動 |
| `check` | 設置を確かめる（Node.js の版、ビルドの新しさ、設定ファイル、画面のファイル、データのフォルダーに書き込めるか、利用者、サービスの定義、動いているサーバーの版、cron）。要対応があれば終了コード 1 |
| `user-add <名前>` | 利用者を足す（パスワードを 2 回聞く） |
| `user-passwd <名前>` | パスワードを変える（その利用者のログイン中の端末はログアウトされる） |
| `user-mfa-reset <名前>` | 2 段階認証を外す（認証アプリを使えなくなり、バックアップコードもないとき。sessionSecret を変えたとき） |
| `user-del <名前>` | 利用者を消す（ログインできなくするだけ。記録のフォルダーは残す） |
| `user-list` | 利用者の一覧 |
| `import-isj <file...>` | 位置参照情報の zip を入れる（大字・町丁目は DB へ、街区は置き場所の確認だけ）。地点への割り当てはしない |
| `assign-areas` | すべての地点の住所を付け直す（保守用。ふだんは取り込みのたびに自動） |
| `import-takeout <zip..>` | Google Takeout の zip（フォルダーでもよい）から保存した場所・ラベル・保存リストを入れる。地点への割り当てはしない |
| `import-swarm <zip>` | Foursquare Swarm の書き出しの zip からチェックインを入れる。地点への割り当てはしない |
| `import-osm-poi <file>` | OSM の名前の付いた施設（osmium export -f geojsonseq の出力）を入れる。地点への割り当てはしない |
| `osm-poi-keys` | 入れてある OSM の施設から、名前で探す索引だけを作り直す（`import-osm-poi` でも作る） |
| `fetch-osm [--user 名前] [--limit N] [--min-wait S] [--max-wait S]` | Nominatim から、まだ調べていない地点の住所を最大 N 件（既定 150）取る。--user がなければ全員の分を順に回しながら。間隔は既定 15〜25 秒（下限 15 秒） |
| `osm-lookup <lat> <lng>` | 1地点だけ Nominatim に住所を問い合わせて表示する（保存しない） |
| `import <file>` | エクスポートファイル（.gz も可）を取り込む |

## 設定（gtexp.config.json）
`host`、`port`、`dataDir`、`isjDir`（位置参照情報の zip。既定は dataDir/isj）、`takeoutSameM`（Takeout の保存した場所を同じ場所とみなす距離。既定 2m）、`takeoutNearM`（同じ場所の滞在先がない保存した場所を、いちばん近い滞在先 1 か所に付ける距離。既定 30m。`takeoutSameM` 以下なら付けない）、`takeoutLabelM`（ラベルの距離。既定 30m）、`labelStopM`（経路がラベルを付けた場所のこの距離以内に来たら立ち寄りとみなす。既定 50m）、`osmEndpoint`（Nominatim）、`osmUserAgent`、`publicDir`、`sessionSecret`（空なら `data/session.key` を自動生成）、`sessionDays`、`mapsApiKey`、`mapId`、`tzOffsetMinutes`。
起動時のログに、起動の日時・バージョン・Node.js の版・利用者の数・ビルドの日時と、秘密の値（項目名に secret / password / key / token / hash を含むもの。設定してあるかどうかだけ出す）以外の全部の設定を 1 項目 1 行で出す。設定ファイルに書いていない項目には「（既定）」を付け、設定ファイルにあっても使っていない項目（古い項目や書き間違い）を知らせる。publicDir に index.html がなければ注意を出す。
相対パスは設定ファイルの場所が基準。設定ファイルは、環境変数 `GTEXP_CONFIG` → カレントの `gtexp.config.json` → `server.mjs` の一つ上（展開したフォルダー）→ `server.mjs` と同じフォルダーの順に探す。`publicDir` の既定は `./dist/public`。

## アプリ名・バージョン（Profile.ini）
リポジトリ直下の `Profile.ini` に、アプリ名などの定数がある。著作者だけが書き換え、プログラムからは読むだけ。

- `tools/profile.mjs` が読んで `src/shared/profile.gen.ts`（`PROFILE`。git には入れない）を作る。npm の dev:*・build:*・typecheck・cli の前に自動で動く
- ページの題名（index.html の `__APP_TITLE__`）と manifest の name・short_name は、vite.config.ts が入れる
- ビルドの情報（元にしたコミット・コミットしていない変更を含むか・ビルドの日時）は、`tools/buildinfo.mjs` が `src/shared/build.gen.ts`（`BUILD`。git には入れない）に書く。build:client・build:server の前に自動で動き、dev:*・typecheck・cli の前は、なければ「開発用」として作る。Git のない場所でビルドしたときは、コミットは「不明」

| 値 | 使う所 |
|---|---|
| [Title] Text / ShortText | ログイン画面・見出しのメニューの「〇〇について」・ページの題名・manifest、書き出しの題名、GPX の creator、OSM に送る User-Agent（`略名/バージョン (正式名; personal use)`）、起動時と使い方の表示 |
| [Version] Text | ログイン画面・このアプリについて、GPX の creator、User-Agent、起動時と使い方の表示。package.json の version も同じ値にそろえる（違うと profile.mjs が注意を出す） |
| [Copyright] Text | ログイン画面・このアプリについて、使い方の表示 |
| [URL] Project | このアプリについて（プロジェクトの URL と LICENSE へのリンク） |
| [AppId] Namespace・[URL] Notice・[Version] Number・[Copyright] Name | PROFILE に入れてあるが、今は使っていない |
