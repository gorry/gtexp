# 概要（フロントエンド・バックエンド）

G Timeline Explorer（略名 gtexp）に興味を持った人向けの、軽い紹介。方針と理由は [design.md](design.md)、機能の詳細は [spec.md](spec.md)、元データの形式は [timeline-format.md](timeline-format.md)。

## 全体像

Google マップのタイムラインは、外から読み出す API がない。そこで、利用者が手動でエクスポートした JSON を自分のサーバーに送って貯め、ブラウザで眺めたり調べたりする。

```
スマホ・PC ──エクスポートした JSON──▶ 自前サーバー（Node.js + SQLite）
     ▲                                    │
     └────── PWA（画面）と API ◀───────────┘
```

## フロントエンド（画面）

- **Preact + TypeScript + Vite**
  - React 互換で軽量な Preact を使う
  - ルーターなどのライブラリは使わず、`#/day/2024-05-25` や `#/place/…` のような URL の `#` 以降で画面を切り替える
- **PWA**
  - パソコンと Android の両方で、同じ画面をそのまま使える
  - Android ではホーム画面にインストールできる。Web Share Target に対応しているので、Google マップでエクスポートした直後に「共有 → gtexp」の数タップでサーバーへ送れる
- **地図は Maps JavaScript API**
  - 場所は Google マップや Google Earth でも開ける
  - 店名は Places API で取らない（規約で保存できず、料金もかかる）。代わりに、場所ごとに自分で名前・タグ・メモを付ける
- **主な画面**
  - 日付：その日の移動と滞在
  - 場所：よく行く場所の一覧と詳細
  - 集計：期間ごとの集計
  - 旅行
  - 保存リスト：Google Takeout から取り込んだ保存リスト
  - 取り込み
- **「このアプリについて」**
  - 画面側とサーバー側のビルドのコミットを並べて出す。食い違っていれば、古い画面がキャッシュに残っていると分かる

## バックエンド（サーバー）

- **Node.js（22.13 以上）+ TypeScript**
  - HTTP サーバーは標準の `node:http` で、フレームワークは使わない
  - 画面と同じ言語なので、API の型（`src/shared/types.ts`）を画面と共有する
- **SQLite は Node 標準の `node:sqlite`**
  - ネイティブモジュールのビルドが要らないので、Linux でも FreeBSD でも素直に動く
  - データベースは利用者ごとに 1 ファイル
- **配布は 1 ファイル**
  - esbuild で `dist/server.mjs` 1 つにまとめる。動かすときに追加のパッケージは要らない
  - 前段に Apache か nginx を置いて HTTPS を受け、Node.js へ中継する
- **取り込み**
  - 100MB を超える JSON も扱う
  - エクスポートには毎回全期間が入っているので、新しいファイルの最初の時刻より後をまとめて入れ替える。自分で付けた名前・メモは別のテーブルにあるので消えない
- **住所・地点名は、保存してよいデータから推定**
  - 国土交通省「位置参照情報」から住所
  - OpenStreetMap から施設名（手元に置いたデータ）と住所（Nominatim で少しずつ）
  - Google Takeout の保存した場所・クチコミも取り込む
  - 優先順位は、自分で付けた名前がいちばん上、次に Takeout
- **`check` コマンド**
  - 設定や動作の状態を点検する。`/api/health` が返す起動時刻とビルドのコミットで、更新が本当に反映されているかも確かめる
